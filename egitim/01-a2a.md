# 01 · A2A (Agent2Agent) Protokolü

> **Tek cümle:** A2A, iki AI agent'ının birbirine iş devretmesi için ortak bir dildir. Joule, bizim yazacağımız agent'la bu dilde konuşacak.

---

## 1. Neden var?

Bir şirkette çok sayıda agent olduğunu düşün: biri SAP içinde (Joule), biri LangGraph ile Python'da yazılmış, biri Microsoft'ta, biri Google'da. Hepsi farklı framework, farklı dil, farklı bulut.

A2A olmasaydı her ikili için ayrı entegrasyon kodu yazılırdı. A2A ile herkes aynı kurala uyar: "Bana şu formatta iş gönder, ben de şu formatta cevap döneyim."

**Benzetme:** A2A, agent'lar arasındaki **e-posta standardı** gibi. Gmail kullanan biri Outlook kullanana mail atabilir, çünkü ikisi de aynı standarda uyuyor. A2A'da da Joule, Python'da yazılmış agent'ına iş gönderebilir. İçinde hangi framework olduğu Joule'yü ilgilendirmez.

A2A'yı Google başlattı, şimdi açık bir standart (Linux Foundation altında, doğrulanmadı). SAP bunu benimsedi. **SAP'nin kullandığı sürüm: A2A 0.3.0.**

---

## 2. A2A ile MCP'nin farkı (sınavda kesin çıkar)

İkisi sık karıştırılıyor, çünkü ikisi de "agent'ı bir şeye bağlamak" ile ilgili.

| | **A2A** | **MCP** (Model Context Protocol) |
|---|---|---|
| Kim kimle konuşuyor | Agent ↔ agent | Agent → tool (araç) |
| Ne gönderiliyor | Bir **görev** ("bu satış teklifini optimize et") | Bir **fonksiyon çağrısı** ("BusinessPartner tablosundan 10 satır getir") |
| Karşı taraf düşünür mü | Evet, karşı taraf da kendi kafasıyla plan yapar | Hayır, tool sadece verileni yapar |
| Sohbet | Çok turlu olabilir, karşı taraf geri soru sorabilir | Tek seferlik istek ve cevap |
| Benzetme | Müdürün işi bir uzmana devretmesi | Uzmanın hesap makinesini kullanması |

**Akılda tutma cümlesi:** *A2A ile işi kime vereceğini seçersin, MCP ile o kişi hangi aleti kullanacağını seçer.*

SAP'nin mimarisinde ikisi birlikte kullanılıyor:

```
Kullanıcı
   │  "Son satış talebini optimize et"
   ▼
 Joule  ──────── A2A ────────►  Bizim Agent (Python / LangGraph)
 (orkestra şefi)                     │
                                     │ MCP
                                     ▼
                              MCP Server (Integration Suite MCP Gateway)
                                     │
                                     ▼
                              S/4HANA API, Datasphere, vb.
```

## 3. A2A'nın temel parçaları

Bu terimleri bilmeden SAP dokümanını okuyamazsın. Altı tane:

### 3.1 Agent Card (agent'ın kartviziti)

Her A2A agent'ı, kendini tanıtan bir JSON dosyası yayınlar. Adres her zaman aynıdır:

```
https://<agent-adresi>/.well-known/agent-card.json
```

İçinde neler var:
- `name`, `description`: Agent ne iş yapar
- `url`: Nereden çağrılır
- `skills`: Hangi işleri bildiği (örn. "döviz kuru çevirme")
- `capabilities`: Streaming destekliyor mu, push notification atabiliyor mu
- `securitySchemes`: Nasıl kimlik doğrulaması istiyor

**Benzetme:** LinkedIn profili. Karşı taraf önce kartı okur, "bu agent bu işi yapar mı?" diye karar verir.

### 3.2 Message (mesaj)

Agent'lar arasında giden tek bir konuşma parçası. İçinde:
- `role`: `user` (gönderen) veya `agent` (cevap veren)
- `parts`: Asıl içerik. Üç tip var:
  - **TextPart**: düz metin
  - **FilePart**: dosya
  - **DataPart**: yapılandırılmış JSON

⚠️ **SAP kısıtı:** Joule şu an sadece `text` tipini gönderiyor. Yani agent'ına giden her şey düz metin olacak.

### 3.3 Task (görev)

Agent'a verilen iş. Bir yaşam döngüsü var:

```
submitted ──► working ──► completed   ✅
                 │
                 ├──► input-required   (agent kullanıcıya soru soruyor)
                 ├──► auth-required    (ek yetki lazım)
                 ├──► failed           ❌
                 ├──► canceled
                 └──► rejected
```

`completed`, `failed`, `canceled` ve `rejected` **son durumdur**, o görev bir daha başlatılamaz.

**Hackathon için kritik olan:** `input-required`. Agent eksik bilgi fark ederse (örn. "Hangi satış talebi?") bu durumla Joule'ye geri döner, Joule kullanıcıya sorar. Buna **Human-in-the-Loop** denir ve jüri bunu sever.

### 3.4 Artifact (çıktı)

Görev bitince agent'ın ürettiği sonuç. Message'ın içindeki Part'lardan oluşur. Joule tarafında sonucu genellikle şu yoldan okursun:

```
apiResponse.body.artifacts[0].parts[0].text
```

### 3.5 contextId ve taskId (hafıza)

- **taskId**: Bu görevin numarası. Agent oluşturur.
- **contextId**: Birbiriyle ilgili görevleri bir sohbet altında toplar. Agent oluşturur.

Joule bu ID'leri cevaptan alır, saklar ve bir sonraki mesajda geri gönderir. Böylece agent "az önce ne konuşuyorduk" bilgisini kaybetmez. Buna **multi-turn** (çok turlu) konuşma denir.

### 3.6 Metotlar (ne istenebilir)

| Metot | Ne yapar |
|---|---|
| `message/send` | Mesaj gönder, cevabı bekle. **Joule bunu kullanıyor.** |
| `message/stream` | Mesaj gönder, cevabı parça parça al (SSE) |
| `tasks/get` | Bir görevin durumunu sor |
| `tasks/cancel` | Görevi iptal et |
| `tasks/pushNotificationConfig/set` | "İş bitince şu adrese haber ver" diye webhook tanımla |

Taşıma (transport) olarak üç seçenek var: **JSON-RPC 2.0** (en yaygın), gRPC ve HTTP+JSON (REST). SAP Agent Gateway HTTP+JSON kullanıyor, Joule'nin pro-code örnekleri JSON-RPC kullanıyor.

## 4. SAP'de A2A: iki yön

SAP'nin mimarisinde A2A **iki yönde** çalışıyor. Bunu karıştırmamak lazım.

### 4.1 Outbound A2A: "Bring Your Own Agent" (BYOA) ⭐ Hackathonda bu

**Joule → bizim agent.** Joule müşteri, bizim agent sunucu.

```
┌──────────┐   1. "Satış teklifini       ┌─────────┐
│ Kullanıcı│ ──── optimize et" ────────► │  Joule  │
└──────────┘                             └────┬────┘
                                              │ 2. Hangi scenario'ya uyuyor?
                                              │    → "sales_optimization"
                                              │ 3. Function içinde
                                              │    agent-request action'ı var
                                              ▼
                                   ┌─────────────────────┐
                                   │ BTP Destination     │  (agent'ın adresi
                                   │ "SALES_AGENT"       │   ve auth bilgisi)
                                   └──────────┬──────────┘
                                              │ 4. A2A message/send
                                              ▼
                                   ┌─────────────────────┐
                                   │ Bizim Agent         │
                                   │ (Cloud Foundry'de)  │
                                   │ LangGraph + a2a-sdk │
                                   └──────────┬──────────┘
                                              │ 5. LLM çağrısı
                                              ▼
                                   ┌─────────────────────┐
                                   │ AI Core /           │
                                   │ Generative AI Hub   │
                                   └─────────────────────┘
```

Adım adım ne olur:
1. Kullanıcı Joule'ye yazar.
2. Joule'nin planlama motoru isteği bir **scenario**'ya eşler.
3. Scenario bir **function** çağırır. Function'ın içinde `type: agent-request` action'ı vardır.
4. Joule, **destination** üzerinden bizim agent'a A2A `message/send` atar.
5. Agent düşünür, gerekirse LLM'i ve tool'ları çağırır, sonucu artifact olarak döner.
6. Joule sonucu kullanıcıya gösterir.

**Senkron mu asenkron mu?**
- **Senkron:** Joule cevabı **60 saniye** bekler. Hackathon demosu için genelde bu yeter.
- **Asenkron:** İş uzun sürerse agent, Joule'nin verdiği webhook'a push notification atar. Joule "arka planda çalışıyorum" der, sonuç hazır olunca gösterir.

⚠️ **60 saniye kuralı önemli.** Agent'ın yavaşsa (çok LLM çağrısı, büyük veri) demoda zaman aşımına düşersin. Ya hızlı tut ya asenkron yap.

### 4.2 Inbound A2A: Agent Gateway

**Dış dünya → Joule agent'ları.** Dışarıdaki bir agent (örn. Microsoft Copilot, Amazon Quick) SAP'nin Joule agent'larını çağırır.

- **Agent Gateway**: SAP'nin yönettiği, internetten erişilebilen bir giriş kapısı. İsteği doğru Joule agent'ına yönlendirir.
- Kimlik doğrulama: **IAS App2App token**, isimli kullanıcı bağlamıyla (yani "kim çağırıyor" belli).
- Hepsi SAP Cloud ALM'de loglanır.
- İstersen önüne **Integration Suite** konur: rate limiting, monitoring, governance.

⚠️ Durum: Inbound A2A Ekim 2026'da GA oldu. Agent Gateway üzerinden **outbound** (SAP agent'ının dış agent'a iş devretmesi) henüz yol haritasında. Detay `09-agent-gateway-inbound.md`'de.

Hackathonda muhtemelen bununla uğraşmayacağız, ama sunumda "agent'ımız ileride Agent Gateway üzerinden Copilot'tan da çağrılabilir" demek iyi bir vizyon cümlesi.

## 5. Kimlik: en çok takılınan yer

Kısa özet (detay `04-kimlik-ias.md`'de gelecek):

- Joule ile agent arasında **IAS App2App trust** kurulması gerekiyor. IAS, SAP'nin kimlik servisi.
- Kullanıcı Joule'ye girdiğinde bir token alır. Joule bu token'ı **değiştirip** (token exchange) agent'a gönderir. Yeni token'ın hedefi (`aud`) artık bizim agent'tır.
- Agent bu token'ı alıp SAP sistemine (örn. S/4) iletirse, S/4 işlemi **gerçek kullanıcının yetkisiyle** yapar. Buna **principal propagation** denir.
- Demo için destination'ı `NoAuthentication` ile kurmak mümkün, ama bu agent'ı herkese açık bırakır. Sadece demo içindir, üretimde asla.

## 6. Joule tarafında yazılacak YAML (ilk bakış)

Detay `08-joule-cli-capability.md`'de. Şimdilik şekli görmen yeterli:

**capability.sapdas.yaml**: projenin kimliği
```yaml
schema_version: 3.27.0          # en az 3.27.0, yoksa agent-request çalışmaz
metadata:
  namespace: joule.ext          # zorunlu, başka bir şey yazarsan deploy hata verir
  name: currency_agent_capability
  version: 1.0.0
system_aliases:
  CURRENCY_AGENT:
    destination: CURRENCY_AGENT # BTP'deki destination adıyla BİREBİR aynı olmalı
```

**functions/call_agent.yaml**: agent'ı çağıran kısım
```yaml
action_groups:
  - actions:
      - type: agent-request     # A2A çağrısı bu
        system_alias: CURRENCY_AGENT
        agent_type: remote
        result_variable: "apiResponse"
      - type: message
        message:
          type: text
          content: "<? apiResponse.body.artifacts[0].parts[0].text ?>"
```

## 7. Agent tarafında yazılacak kod (ilk bakış)

Python'da resmi `a2a-sdk` kütüphanesiyle. Detay `07-pro-code-agent.md`'de.

İki parça var:
1. **AgentExecutor**: Gelen mesajı alır, agent'ı çalıştırır, durumu günceller (`working`, `input-required`, `completed`).
2. **A2AStarletteApplication**: Agent Card'ı yayınlar ve HTTP isteklerini karşılar.

```python
class MyAgentExecutor(AgentExecutor):
    async def execute(self, context, event_queue):
        query = context.get_user_input()              # Joule'den gelen metin
        task = context.current_task or new_task(context.message)
        updater = TaskUpdater(event_queue, task.id, task.context_id)

        result = await my_langgraph_agent.run(query)  # asıl iş burada

        await updater.add_artifact([Part(root=TextPart(text=result))])
        await updater.complete()                      # task → completed
```

## 8. Takılma noktaları (hata → sebep)

| Belirti | Sebep |
|---|---|
| Deploy'da `User is not authorized to deploy sap capabilities (5014)` | Namespace `joule.ext` değil |
| `agent-request` tanınmıyor | `schema_version` 3.27.0'dan küçük |
| Joule agent'ı bulamıyor | Destination adı ile `system_alias` birebir aynı değil |
| `joule login` → `AUTH_FETCH_TOKEN_FAILED` | joule-cli 2.0.2 hatası, `joule login --no-app-tid` kullan |
| Joule cevap gelmeden pes ediyor | 60 saniye limiti aşıldı, asenkron yap |
| Joule cevabı boş gösteriyor | `artifacts[0].parts[0].text` yolu agent'ın döndüğü yapıyla uyuşmuyor |
